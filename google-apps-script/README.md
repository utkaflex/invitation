# Подключение регистрации

Это подготовленный обработчик, ещё не подключённый к сайту. Не меняйте адрес
отправки в index.html вручную: сначала требуется проверить опубликованный endpoint
из браузера сайта, включая чтение JSON после редиректа Google (CORS).

1. Откройте существующую Google Форму в режиме редактирования.
2. В меню ⋮ откройте «Редактор скриптов» / Apps Script.
3. Вставьте содержимое Code.gs в файл скрипта. Если там уже есть код,
   сохраните его и добавьте отдельный файл; функции doGet/doPost не должны дублироваться.
4. Сохраните, выберите функцию setup и нажмите «Выполнить».
   Разрешите вашему скрипту доступ к форме. setup проверяет поля и сохраняет ID,
   но не создаёт тестовых заявок и не меняет вопросы.
5. «Развернуть» → «Новое развертывание» → «Веб-приложение».
   Выполнять от вашего имени; доступ — «Все» (включая гостей без Google-аккаунта).
   Этот публичный адрес принимает заявки, но не выдаёт ответы или данные гостей.
6. Скопируйте URL, заканчивающийся на /exec, и передайте для подключения сайта.

## Перед публикацией сайта

- Проверить публичный GET: service=70aero-registration, configured=true.
- Подключить отправку POST с URLSearchParams, без no-cors и без JSON Content-Type.
  Передавать существующие entry.*, consent=yes и постоянный requestId (UUID).
- Показывать успех только при читаемом JSON ok=true, code=saved и совпадении requestId.
- При сетевой ошибке сохранять поля и тот же requestId для повторной попытки.
  Таймаут браузера не отменяет запись на сервере.
- Проверить в браузере с домена сайта чтение JSON, медленную сеть, двойной клик,
  повтор после обрыва, неверные поля, закрытую регистрацию и сценарий без входа Google.
- Согласовать контрольную заявку и сверить её в ответах формы. Пока этого нет,
  работоспособность интеграции целиком не подтверждена.

## Ограничения

Скрипт использует квоты Google Apps Script и по-прежнему зависит от доступности Google.
Записи защиты от дублей хранят хеш полей и состояние, без исходных контактных данных.
Одинаковый requestId не отправляется повторно. При неопределённом состоянии uncertain
нужна сверка у организатора, а не автоматическая новая заявка. Защита не распространяется
на независимые заявки с новыми ID. Script Properties имеет ограниченный объём;
решение рассчитано на небольшое мероприятие, не на массовую регистрацию.
Публичный endpoint не защищён полноценной CAPTCHA; website — только поле-ловушка.
Скриптовая отправка не запускает обычные installable onFormSubmit triggers:
если организаторы используют автоматические письма, их нужно отдельно проверить.

Документация: https://developers.google.com/apps-script/guides/web
и https://developers.google.com/apps-script/reference/forms/form-response
